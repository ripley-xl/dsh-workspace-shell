# 会话发送失败与跨页签草稿传递

日期：2026-11-04。实现版本：Shell `0.5.2` / SSH `0.3.1`，已安装到 Desktop 与本机 Web，Desktop 已重启。
本文按用户最新确认更新，取代只读预览、列表图标和新建页签确认框方案。

## 范围

本机 Desktop 与 Web Host 共享会话存储时，会话可能由另一个进程持有写锁。用户仍使用原生会话列表、历史和输入框；插件不提前限制发送，不提供独立只读预览。

框架、Host 登记和会话导航属于核心功能，不单独列成可关闭组件。SSH 是默认开启的可选子组件，关闭 SSH 不影响本机会话导航。

## 交互

1. 点击会话时照常打开，不跳转、不弹窗、不增加侧栏标记。
2. 用户发送后，只有实际返回 `session/writer-held` 才查询登记的 Host，并在输入框上方显示简短提示。
3. 找到占用者时显示“此会话正在 web Host 中使用。”以及“前往页签”或“打开页签”。用户点击后才导航，无额外确认框。
4. 目标页签打开同一会话，把本次发送失败的文字放入输入框，显示“已带入未发送的文字，请检查后发送。”
5. 用户自行检查并点击原生发送按钮。导航和草稿传递均不自动发送。

网络错误、模型错误和其他发送错误沿用 DSH 原有处理。DSH 自带的占用错误提示仍会短暂出现，插件不修改宿主提示。

## 文字保留

- 在提交入口捕获失败请求的文本，不从跳转时的输入框重新读取。
- 来源输入框保持原样，包含用户在失败后继续修改的文字。
- 目标已有草稿时，以新段落追加，不覆盖目标原文或已有附件。
- 同一次失败重复点击，在同一目标 Client 生命周期内只带入一次。目标页签重载后去重记录会清空，重试可能再次追加。
- 只传递文本。图片、文件等附件仍留在原页签，提示明确说明；用户需自行处理附件。
- 草稿数据的序列化大小最多 48 KiB。超限时留在来源并提示，不静默截断。
- 目标输入框忙、目标已变化、接收回执缺失或导航取消时，不报告成功。来源文字始终保留。
- 取消可能发生在目标已收下文字之后，因此取消不保证目标未追加。后续重试使用相同传递 ID 去重，不回滚用户输入。

## 页签选择

目标按 Host 实例、窗口、页签和会话 ID 匹配，不按 profile 名、端口或标题匹配。

1. 优先复用已经显示目标会话的页签。
2. 其次复用连接同一 Host 的最近使用页签；宿主保留其原会话草稿。
3. 没有匹配页签时，接入指定的现有 Host 并打开会话。不得启动同名替代 Host。
4. 等待目标会话准备就绪，通过公开草稿接口追加文字，校验匹配的草稿回执后再确认导航完成。

嵌入式 Guest 把跳转请求交给父框架执行，因此同一窗口内支持两个方向的跳转。目标无法安全接入时说明限制，不读取其他进程的凭据文件，也不猜测其他系统窗口的位置。

## Host 退出

会话不永久绑定到创建它的 Host。原 Host 退出释放写锁后，当前 Host 可以按 DSH 原生流程继续会话。

登记失联、请求超时或没有 Agent 报告都不能证明写锁已释放。此时显示“暂未定位到占用者；原 Host 已退出时，可在这里重新发送。”，不禁用输入或替用户接管。

## 实现与验证

- `session-host/submissions.js` 观察公开 `Session.prompt()` 结果，保留原始发送行为、返回值和草稿恢复。
- `session-host/controller.js` 协调登记、定位、指定会话选择及草稿回执。
- `session-host/ui.js` 仅注册 `conversation.input.dock`，不替换侧栏或聊天内容。
- `src/host/session-views.js` 对草稿、视图身份、超时和回执进行校验。草稿不进入发现列表，只保留在内存中的待处理请求。
- 每个参与 Host 都要加载新版 Shell；仅升级 Desktop 无法发现未参与登记的 Web Host。
- 第一版只处理本机共享 JSONL 存储，不合并隔离存储，也不提供跨机器 SSH 会话迁移。

隔离双 Host 测试和真实 Desktop / Native Web Guest 均已覆盖真实写锁冲突、点击后接入、精确失败文本、追加、双向跳转、来源后续编辑保留、无自动发送，以及原 Host 退出后的原生恢复。当前 Client 内重复跳转去重及关闭视图后的原 Host 重新接入也已实测。

0.5.2 修复了 SSH Client 在嵌入页等待 `workspaceShell` 服务导致启动失败的问题。嵌入页不声明这一依赖，也不挂载独立 SSH 界面；核心会话登记继续运行。浏览器回归同时加载 SSH。

实机仍有两项边界：其他 Host 新建会话未立即出现在已运行 Desktop 的原生目录，重启后可见；关闭 Native Guest 后新建的 Client 不恢复旧 Guest 草稿。此插件不保证跨 Client 重建保存草稿。Native 附件与引用 chip 的完整保留流程仍待验收。
