# DSH SSH Remote 设计规格

状态：切换式窗口方向已确认，待规格终审

## 1. 已确认的决策

采用“本地连接管理插件 + 远端完整 DSH Web Host + 同标签页整页切换”。

核心决策如下：

1. 用户按机器切换工作区：本地，或某一台 SSH 远程主机。
2. 本地使用当前本地 profile，远端使用 `web` profile。
3. 普通浏览器通过完整页面导航切换；Desktop 在当前窗口内使用沙箱 Webview 多页签，不触发外部浏览器。两种形态都不混合两个 Host 的 Client、插件、配置或 Session。
4. SSH Remote 只连接插件自带运行包启动的远端实例；其他运行包的实例是独立的，安装或升级不覆盖也不停止它们。
5. 本机插件通过脱敏快照展示在远端页面，官方可选插件启停沿用本机；用户从远端插件页一键安装其他插件，现有插件机制不需要增加 `executionTarget`。
6. 支持选定配置的本地到远端单向同步，包括主题和模型提供商配置。
7. 用户授权后，API Key 可以复制到远端，并写入远端 credentials，不写入 patch 或日志。
8. 不修改其他插件的目标模型。任何时刻，当前页面只对应一个 Host、一个 profile 和一个执行环境。

此前讨论的“单窗口混合本地与远端项目”不在本方案内。

## 2. 背景与依据

### 2.1 DSH 现有能力

DSH Web 已由 Host 提供静态页面、RPC、流式接口、Client 插件图和访问令牌。`dsh web` 支持指定监听地址、动态端口、公开 URL 和可信 Host。远端运行完整 Web Host 后，可以复用现有文件、终端、Session、插件市场和配置能力。

DSH 的插件与配置均以当前 profile 为边界。只要每次页面导航后仍只面对一个 profile，就不需要改变现有插件的运行假设。

### 2.2 参考产品

主要参考 VS Code 的 Remote 与 Agent Host SSH 思路：

- 本地产品版本决定远端 server/CLI 版本；
- 自动安装、校验和复用远端运行包；
- 控制面负责安装、启动、发现和健康检查；
- 数据面承载工作区 UI、文件、终端和 RPC；
- 远端进程独立于单次 SSH 连接存活；
- 断线后优先恢复原实例，而不是重装或重启所有进程。

本插件不采用第一条：远端版本由插件自带的运行包决定，本机 DSH 版本只影响运行包偏好。VS Code 经典 Remote-SSH 扩展本体不在当前源码检出中，本规格只采用可从源码确认的运行时安装、端点管理和重连原则，不假定其内部实现细节。

## 3. 目标与非目标

### 3.1 目标

1. 用户配置 SSH 主机后，无需手动安装或升级远端 DSH。
2. 远端 DSH 版本由插件自带的运行包决定，与本机 DSH 版本解耦。
3. 用户可在同一浏览器标签页中切换本地与某台远程主机。
4. 切换后使用对应机器的完整 profile、插件、配置和工作区。
5. 文件、搜索、终端、Agent 和插件市场操作均作用于当前页面所属机器。
6. 支持本机插件快照、官方启停同步和一键安装到远程，现有插件无需理解远程目标。
7. 支持主题、模型提供商和授权 API Key 的单向同步。
8. SSH 断开不直接终止远端 Host、Agent 或终端，网络恢复后优先恢复原实例。
9. 不削弱 SSH 主机密钥检查、DSH 浏览器认证、插件安装批准和权限策略。

### 3.2 首版非目标

- 在同一个 DSH 页面中混合展示本地与远端 Workspace 或 Session；
- 为插件增加 `executionTarget` 或双端运行声明；
- 本地与远端配置的双向或持续自动同步；
- 默认复制全部本地插件和配置；
- Windows 本地端或远端；
- 密码、私钥口令和 keyboard-interactive SSH 认证；
- ProxyJump 和 ProxyCommand；
- 通用端口转发；
- 本地 Host + 远端执行提供方的第二种模式。

## 4. 用户体验

### 4.1 本地主机管理

本地 DSH 左侧增加“SSH 主机”入口。管理页包含：

- 当前环境：本地，或某台 SSH 主机；
- 本机 OpenSSH 配置中的主机列表，支持搜索和手动别名；
- 本机插件快照与官方启停同步状态；
- 添加、编辑、切换、停止、升级、同步和删除操作；
- 分阶段进度与脱敏诊断日志。

管理页通过 `sidebar.panellist` 和 `main` 注册，不替换现有工作区或会话页面。

### 4.2 切换到远程

用户点击“切换到远程”后，管理器依次执行：

1. 解析 SSH 配置；
2. 验证主机密钥并完成认证；
3. 检查远端平台、现有安装和运行实例；
4. 安装或校验插件自带的 DSH 运行包；
5. 启动或复用该运行包的远端实例；
6. 建立本地 Loopback Gateway；
7. 上传本机插件快照并同步官方启停；
8. 同步选定配置与授权 API Key；
9. 等待远端 profile 和 Client 插件图稳定；
10. 在当前标签页中导航到远端 Web 的认证 URL。

可选插件同步失败时显示部分完成状态，但不得把失败项报告为成功。基础 Web Host 或运行包校验失败时禁止切换。

### 4.3 远程工作区

远程页面由远端 Web Host 提供，使用远端 `web` profile。用户看到的是该远端自己的工作区、Session、插件、插件市场和配置。

当前页面显示 `SSH: <主机别名>`。文件树、终端、Agent 和插件操作不需要知道其他机器存在。

### 4.4 切换回本地

远程状态插件提供“切换到本地”操作，导航回本地 DSH 基础地址。浏览器历史返回可作为辅助方式。

本地访问令牌不写入远端。返回时使用浏览器已有的本地认证状态；需要重新认证时由本地 DSH 处理。

本地 Host 在页面离开期间继续保持 SSH 管理和网关状态，返回后显示最新连接状态。

### 4.5 多远程与多标签页

一个标签页在任一时刻只显示一个环境。用户可以切换到另一台远程主机，也可以在不同标签页中分别打开本地和远程页面。

多个标签页不改变 profile 隔离，也不意味着同一个页面混合了多个执行环境。

## 5. 总体架构

```text
同一个浏览器标签页
┌──────────────────────────────────────────────┐
│ 本地页面 ⇄ 整页导航 ⇄ 远端 Web 页面            │
└──────────────────────────────────────────────┘

本地 DSH Host（当前本地 profile）
┌──────────────────────────────────────────────┐
│ SSH 管理插件                                  │
│  ├─ 主机、版本与连接管理                       │
│  ├─ 插件快照、官方启停与配置同步               │
│  ├─ SSH 控制通道                               │
│  └─ Loopback Gateway                          │
└───────────────────┬──────────────────────────┘
                    │ SSH 控制 + direct-tcpip
                    ▼
远端主机
┌──────────────────────────────────────────────┐
│ Remote Controller + Instance Supervisor       │
│  ├─ 版本化安装与升级                           │
│  ├─ 实例注册、租约和健康检查                   │
│  └─ 启停与日志                                 │
│                                              │
│ 自带运行包 DSH Web Host（web profile）         │
│  ├─ 工作区、Session 和 Agent                   │
│  ├─ 文件、搜索和终端                           │
│  ├─ 插件、插件市场和配置                       │
│  └─ 远端 credentials                          │
└──────────────────────────────────────────────┘
```

### 5.1 控制面

控制面负责 SSH 配置与认证、平台探测、版本安装、实例管理、插件快照、官方启停和配置同步。它由本地管理插件、Remote Controller 和远端既有管理 API 组成。

### 5.2 数据面

数据面承载远端 Web 静态资源、Client 插件包、RPC、WebSocket 和终端数据。它由远端 DSH Web Host、SSH `direct-tcpip` 通道和本地 Loopback Gateway 组成。

控制面与数据面使用同一 SSH 认证上下文，但采用独立通道。远端程序输出不能伪造控制面响应。

## 6. 组件职责

### 6.1 本地管理插件

Host 半侧负责：

- 主机与同步策略存储；
- 本地 DSH 版本和构建信息读取；
- SSH 连接与认证；
- Remote Controller 调用；
- 实例选择与本地网关；
- 插件快照、官方启停和配置同步；
- 连接状态机与日志脱敏。

Client 半侧负责：

- 主机管理页；
- 版本、安装、同步和连接进度；
- 插件快照、远端插件列表和一键安装；
- 配置同步差异与授权确认；
- 切换、返回和错误展示。

连接、安装、升级、同步、停止和删除只接受经过 DSH 浏览器认证的用户操作。首版不注册可执行这些动作的 Agent 工具。

### 6.2 Remote Controller

Remote Controller 随运行包发布，提供：

| 命令 | 职责 |
|---|---|
| `probe` | 返回 OS、架构、libc、HOME、shell 和目录写权限 |
| `install` | 安装本地 DSH 对应的精确远端版本 |
| `list` | 返回脱敏实例列表及版本信息 |
| `start` | 启动指定版本的新实例 |
| `attach` | 返回实例连接坐标、认证 URL 和客户端租约 |
| `heartbeat` | 续租并返回实例健康状态 |
| `release` | 释放客户端租约，不直接停止实例 |
| `status` | 返回实例健康、客户端数量与活动状态 |
| `stop` | 优雅停止指定实例 |
| `logs` | 返回脱敏日志页 |
| `uninstall` | 删除未被实例使用的旧运行包 |

`start` 先启动 Instance Supervisor，再由 Supervisor 脱离 SSH 启动 DSH Web Host。Supervisor 常驻，负责实例注册、客户端租约、健康检查和空闲退出。

命令使用带 `protocolVersion` 和 `requestId` 的 JSON 输出。普通诊断写 stderr，协议消息独占 stdout。所有命令有界执行并支持取消。

`list` 和 `status` 不返回认证 URL 或访问令牌。只有 `attach` 可以通过已认证的 SSH 控制通道返回这些秘密及 `clientLeaseId`。本地管理器在连接期间每 10 秒续租，主动断开时尽力调用 `release`。

### 6.3 远端 DSH Web Host

远端 Host 使用与本地 DSH 完全相同的版本和 Web 模板。profile 首次初始化后，升级不得覆盖用户 patch、插件选择和同步边界之外的配置。

Host 启动要求：

- 只监听远端 `127.0.0.1`；
- 端口由操作系统分配；
- 不自动打开远端浏览器；
- 显式允许浏览器来源主机名 `localhost`；
- 使用 DSH 进程访问令牌；
- 使用远端默认工作区，不修改无关 profile 配置。

本地管理器用 `http://localhost:<本地端口>` 构造浏览器地址。`--trusted-host localhost` 允许本地端口变化，DSH 令牌和 SSH 通道仍提供访问控制。不得添加通配可信 Host 或关闭浏览器认证。

`attach` 返回远端 Host 启动时生成的完整认证 URL。本地管理器只替换 URL 的协议、主机和端口，保留路径、查询参数和访问令牌，不猜测令牌参数格式。

### 6.4 Loopback Gateway

每个已连接主机有一个本地网关：

- 只绑定 `127.0.0.1`；
- 使用随机空闲端口；
- 在本地插件运行期间保持地址稳定；
- 每个本地 TCP 连接建立独立 SSH `direct-tcpip` 通道；
- 目标只能是选定远端实例的 `127.0.0.1:<实例端口>`；
- 原样转发 HTTP、WebSocket、Cookie、Host 和 Origin；
- 不实现公共代理，不允许调用方指定任意目标地址。

本地应用重启后可以选择新端口。用户重新执行切换即可，远端实例不需要重启。

### 6.5 远程状态插件

SSH Remote 包同时提供一个安装到远端 `web` profile 的状态插件，负责：

- 显示 `SSH: <主机别名>`；
- 提供“切换到本地”；
- 显示远端版本和连接说明；
- 提供远端自身的脱敏日志入口。

该插件不读取本地 credentials，也不把本地访问令牌保存到远端。

### 6.6 Desktop 内嵌与多页签

Desktop 不通过 `window.location.assign()` 打开远端地址。它使用现有 `window.dshDesktop.browser.acquire/release()` 和沙箱 `<webview>`，把远端 DSH Web 嵌入当前窗口的内容区。

插件维护自己的页签：本地一个页签，每台远程主机一个页签。切换页签只隐藏旧 Guest，保留页面状态；关闭页签、卸载、主框架失败或渲染进程退出时才释放 Guest。同一主机不重复 acquire 或加载。关闭 Guest 不调用远端 `stop`。

左侧底部使用 `sidebar.footer.action` 和公开 `layout.selectPanel('ssh-remote')` 提供切换入口。账户菜单当前没有扩展 Slot，不通过 DOM 写入菜单。

普通浏览器没有 Desktop bridge 时，仍使用完整页面导航。远端状态插件的返回本地用于普通浏览器；Desktop 由外层页签和返回本地操作处理。

远端 DSH Web 可以常驻。Desktop 关闭或本地管理服务释放只关闭本地网关、SSH 通道和 Guest，不停止远端实例。下次连接按实例身份、版本和构建复用健康实例。

## 7. 运行包选择与安装升级

### 7.1 运行包选择规则

本地 SSH Remote 插件从自带的运行包目录选择远端运行包，本机 DSH 版本只作为偏好：

- 有与本机 DSH 版本匹配的运行包时优先使用；
- 没有匹配版本时使用自带的最新运行包，不要求本机与远端 DSH 版本一致；
- 指定构建标识时只接受该构建；
- `protocolVersion` 或包内自检不匹配时不安装、不复用。

远端实例的运行包身份由 `createdBy`（runtimeId）区分。属于其他 Desktop 的实例不接入、不停止；不同运行包的实例各自运行自己的 DSH 版本。它们共用远端 `DSH_HOME` 与 profile 数据，进程、控制器记录和客户端租约相互独立。

本机 DSH 升级不改变远端运行包；插件自带的运行包更新后，manager 以新运行包另起实例，旧实例作为独立实例保留并按空闲超时退出。

运行包不可用或无法通过自检时，连接失败。不得回退到任意旧版本，不得自动授予插件版本豁免。

### 7.2 运行包

远端运行包包含插件自带版本的 Node 运行时、Remote Controller、DSH CLI、Web 资产和必要原生依赖。首版不要求远端预装 Node、pnpm 或编译工具。

首版发布：

- Linux x64；
- Linux arm64；
- 对应 glibc 或 musl 变体。

不支持的 libc 或架构返回明确错误。

### 7.3 首次引导

首次没有已安装 Remote Controller 时，本地管理器通过固定 POSIX 探测命令获取平台信息，再把自带运行包中的自包含 bootstrap Controller 上传到独立临时目录。校验摘要后，直接以 `install` 模式执行。

引导不依赖远端 Node，也不把远端返回文本拼接成命令。后续操作使用该运行包已安装的 Controller。

### 7.4 安装流程

1. 根据插件自带运行包和远端 `probe` 结果选择固定产物；
2. 检查现有安装目录和摘要；
3. 获取该版本的远端安装锁；
4. 下载或通过 SFTP 上传到独立临时目录；
5. 校验 SHA-256 和包内路径，拒绝绝对路径及越界路径；
6. 原子重命名为不可变版本目录；
7. 执行版本和启动自检；
8. 自检失败时隔离目录，不启动它。

安装不得覆盖正在使用的版本。

### 7.5 升级与回滚

升级由 SSH Remote 自动编排，但不得无提示中断活动工作：

- 有其他客户端、运行中的 Agent、终端或后台任务时，提示用户确认升级窗口；
- 断开本机连接，旧实例按自己的空闲超时退出；
- 启动新运行包对应的实例；
- 按插件快照、官方启停和同步策略恢复声明式状态；
- 新运行包启动失败时保留旧运行包目录和用户数据并报告失败，只有插件也回滚到对应运行包时才允许启动旧实例；
- 保留 Session、profile 和用户数据，不回滚这些数据。

远端已有的其他插件不自动改写。若这些插件阻止该运行包 Host 启动，界面列出具体插件，由用户选择升级或禁用，不自动授予版本豁免。

旧版本只用于本地与远端成对回滚后的故障恢复，不能作为正常连接时的兼容替代。

## 8. 本机与远端插件管理

### 8.1 本机快照与官方启停

首次连接和显式同步时，本地管理器向远端状态插件上传一份本机插件快照。快照只包含名称、安装 spec、版本、来源、公开显示元数据、启停和兼容信息，不包含本地路径、认证 URL、凭据或秘密值。

官方插件不作为远程安装模板。仅对本地与远端都存在的 `official && optional` bundle 同步启停状态；相同状态跳过，不授予版本豁免，不自动安装非官方插件。

快照保存在远端 Host 内存中。若官方启停或插件操作导致 Host 重启，本地管理器在新实例上重传快照，不重复执行已经成功的官方启停。

### 8.2 远端插件页

远端状态插件注册独立的插件管理页，分为：

- **本机插件**：读取最近一次快照，供用户选择需要安装的插件；
- **远端插件**：实时读取远端 `pluginManager` 状态。

本机项可按快照中的精确 spec 一键安装到远端。远端项支持启停和带确认的卸载。安装、启停和卸载只操作当前远端 profile，不修改本机 profile。

官方及 SSH Remote 内置插件不出现在本机待安装列表中。本地路径形式的插件不会直接上传，需有远端可用包源；无法解析时明确显示，不假定安装成功。

### 8.3 兼容与批准

- 检查插件版本、远端 OS/CPU 和原生依赖；
- 构建脚本必须由用户明确批准，pendingBuilds 不得自动执行；
- 不自动授予版本豁免；
- 可选插件失败形成部分完成状态，不影响基础 Web Host；
- 插件操作要求重启时，远端页面显示重启要求，本地管理器在编排重启后重新上传快照。

## 9. 配置与凭据同步

### 9.1 同步模型

首次添加并连接时，默认同步所有支持的用户配置。后续连接只恢复传输，不自动写入配置。用户仍可通过显式同步再次执行。

同步使用本地到远端的单向写入，不是持续双向同步。自动剔除秘密原值、本机路径、本地基础设施配置和当前工作目录。

如果本次写入会覆盖远端已有用户配置或插件状态，必须先在远端创建权限为 `0600` 的备份。备份内容留在远端，报告只包含备份 ID、路径和时间，不向本地返回秘密值。

需要人工合并时，管理页提供可复制的处理提示词。用户可在当前远端开新会话，按备份逐项决定保留、恢复或合并。提示词不包含任何秘密值。

| 配置类型 | 默认策略 | 写入位置 |
|---|---|---|
| 主题、字体和外观 | 允许同步 | 远端对应 settings/config API |
| 模型提供商非秘密配置 | 允许同步 | 远端模型与 settings API |
| API Key、Token | 用户授权后允许 | 远端 credentials |
| OAuth、订阅登录 | 默认远端重新登录 | 远端授权流程 |
| 插件配置 | 按插件和字段选择 | 远端 configEditor/settings |
| 其他 profile patch | 不同步 | 保持在所属端 |

读取时可以展示本地与远端差异。写入只覆盖标记为由 SSH Remote 管理的字段，未纳管字段保持远端原值。

远端同步后的修改独立保留。下次同步再次显示差异，不自动覆盖。

### 9.2 外观同步

外观同步前，预览会标明提供当前主题或外观能力的插件是否已在远端安装；未安装时由用户在远端插件页一键安装。同步内容包括：

- 当前主题 ID；
- 字体与界面字号；
- 用户明确选择的 token 覆盖；
- 已纳入同步策略的主题插件配置。

如果对应插件未安装或不兼容，标记该项失败，不回退后声称同步完成。

### 9.3 模型提供商同步

非秘密配置与凭据分开处理：

1. 同步提供商类型、Base URL、启用的供应商和模型选择；
2. 对支持直接复制的 API Key，在用户授权后读取本地 credentials；
3. 通过加密 SSH 通道写入远端 credentials；
4. 使用远端只读描述或最小模型目录请求验证，不打印秘密；
5. OAuth、设备绑定或订阅授权默认转到远端重新登录。

API Key 不写入 `cordis.patch.yml`、插件快照、普通日志、诊断包或远端命令行参数。

DSH 的本地凭据提供方使用 `<DSH_HOME>/.credentials.yaml`，它是带版本、权限检查和写入锁的私有 YAML 存储，不是普通 `.env`。项目与 Harness Home 下的 `.env` 只是回退来源。同步必须调用远端 `credentials.set()`，由提供方处理原子写入、自动重载、格式校验和优先级，不直接编辑凭据文件。

API Key 类凭据只在首次默认同步或用户显式重新同步时写入。后续连接不自动覆盖，避免本地旧值覆盖远端刚轮换的值。OAuth grant 和 refresh token 不做通用复制，优先在远端重新授权。

本地管理器只保存“允许同步该凭据”的授权记录，不额外持久化一份秘密。

### 9.4 同步调用边界

非秘密配置使用远端 settings/config 管理接口，凭据使用远端 credentials 接口，插件使用远端插件管理器。

首次同步在远端 Web Host 启动并通过网关可达后执行。若插件安装要求重启，先由 Remote Controller 完成重启和稳定检查，再继续同步。

任何 Host 重启都可能产生新的 `instanceId` 和认证 URL。同步或升级完成后必须重新 `attach`，以最新实例、租约和认证 URL 建立最终页面导航；旧租约、旧网关目标和旧 URL 不得继续使用。

不得通过直接修改两端 profile 文件实现运行期同步。

## 10. 数据模型与存储

### 10.1 本地 ConnectionRecord

| 字段 | 含义 |
|---|---|
| `id` | 本地随机、不可复用的连接 ID |
| `name` | 用户显示名称 |
| `hostAlias` | OpenSSH 主机别名 |
| `lastInstanceId` | 最近使用的远端实例，可为空 |
| `lastServerVersion` | 最近使用的远端 DSH 版本 |
| `syncPolicy` | 外观、模型、插件配置和 API Key 同步授权 |
| `lastConnectedAt` | 最近成功连接时间，可为空 |
| `lastSyncedAt` | 最近同步时间，可为空 |
| `createdAt`、`updatedAt` | 本地记录时间 |

本地记录不保存密码、私钥内容、私钥口令、DSH 访问令牌、API Key 或完整 SSH 私钥路径。运行时的在线状态必须重新探测。

### 10.2 远端 RemoteInstanceRecord

| 字段 | 含义 |
|---|---|
| `schemaVersion` | 注册表结构版本 |
| `instanceId` | 每次启动生成的随机 ID |
| `hostPid`、`supervisorPid` | 远端 Host 与 Supervisor 进程 ID |
| `protocolVersion` | Controller 控制协议版本 |
| `dshVersion`、`buildId` | 远端 DSH 版本与构建标识 |
| `endpoint` | 远端回环地址与端口 |
| `authenticatedUrl` | DSH 完整认证 URL |
| `workspace` | 默认远端工作区 |
| `startedAt` | 实例启动时间 |
| `createdBy` | 创建实例的 Controller 安装 ID |
| `idleTimeoutMs` | 实例创建时确定的空闲退出策略 |
| `lastAttachAt` | 最近客户端接入或租约续期时间 |

注册目录权限为 `0700`，记录文件权限为 `0600`。PID 只用于辅助检查，实例身份以 `instanceId` 为准。读取记录时验证 schema、端口、路径和版本，不把文件内容当成可信命令参数。

### 10.3 远端目录

默认目录为 `~/.dsh/ssh-remote/`：

```text
servers/       按 DSH 版本和平台隔离的运行包
instances/     实例注册记录
locks/         安装与实例操作锁
logs/          脱敏运行日志
tmp/           有界临时目录，完成后清理
```

`web` profile、Session 和 credentials 按 DSH 约定存放，不放进 Controller 安装目录。

## 11. 连接状态机与生命周期

### 11.1 状态

```text
idle
  → resolving
  → verifying-host
  → authenticating
  → inspecting
  → installing 或 upgrading
  → attaching 或 starting
  → forwarding
  → syncing-plugins
  → syncing-config
  → ready
  → switching
  → connected

connected
  → reconnecting
  → connected

任意活动状态
  → cancelling
  → idle

任意活动状态
  → failed
  → idle 或 reconnecting
```

后台重连只能进入不需要用户输入的路径。同步需要新授权或构建批准时，后台重连不得自动执行该步骤。

### 11.2 并发与取消

同一 `hostAlias` 的连接请求必须合并。安装、升级和实例启动另用远端锁保护。

取消规则：

- 取消认证：关闭未完成的 SSH 连接；
- 取消安装：停止本次下载并清理本次临时目录；
- 取消启动：只清理由本次操作创建且没有其他客户端租约的实例；
- 取消同步：停止后续步骤，已完成项如实显示，不伪造回滚；
- 取消接入：关闭本地网关和通道；
- 不得停止接入前已经存在的 `external` 实例。

安装、启动、停止和同步结果不确定时不得自动重放。先读取状态，再决定是否安全继续。

### 11.3 managed 与 external

`managed` 实例由当前本地管理器运行期创建，在该运行期的多次重连中保持这个分类。`external` 实例在当前运行期首次接入前已经存在。这个分类是本地生命周期判断，不是注册表中的全局属性。

首次连接取消或主动断开时：

- `managed` 只清理由本次运行期创建、且确认没有其他客户端租约的实例；
- `external` 只释放本地通道和客户端租约，不直接停止实例；
- 用户显式点击“停止”是独立操作，必须再次确认目标 `instanceId` 和活动状态。

### 11.4 空闲退出

每个实例由远端 Supervisor 执行创建时确定的空闲策略。默认只有同时满足以下条件才允许自动退出：

- 没有有效客户端租约；
- 没有运行中的 Agent；
- 没有活动终端或后台任务；
- 已连续空闲 15 分钟。

SSH 断开后，客户端租约在 30 秒内到期，随后才进入空闲计时。Supervisor 通过 DSH 现有 Session、Terminal 和后台任务只读状态接口判断活动；接口不可用或状态不明确时保持运行。

## 12. 重连

1. 标记原通道失效，让等待中的传输请求失败；
2. 保留本地连接记录和远程页面恢复所需信息；
3. 采用 1 秒起步、30 秒上限的指数退避；
4. 每次尝试重新解析 SSH 配置并验证主机密钥；
5. 后台重连不得请求密码、口令、新的主机密钥信任、API Key 授权或构建批准；
6. 按 `instanceId` 查询原实例并验证版本和构建标识；
7. 本地 DSH 已升级时，先执行版本升级，不能继续接入旧实例；
8. 健康且运行包身份一致的实例存在时恢复 `attach` 和网关；
9. 实例不存在时停止自动传输重放，提示用户启动新 Host；
10. 连续 10 次失败后转为 `failed`，提供“立即重连”。

DSH Session 日志决定会话恢复。文件修改、进程启动、插件安装和配置同步等副作用不因 SSH 重连而自动重放。

原 Host 已退出时，可以启动新 Host 恢复持久 Session，但必须明确说明运行中的进程不可恢复。

## 13. SSH 配置与认证

### 13.1 配置解析

SSH 连接、SFTP 和数据通道使用 `ssh2`。系统 `ssh` 只用于执行 `ssh -G <alias>` 获取有效配置，不另建一套 OpenSSH 控制连接。

首版支持：

- `HostName`、`User`、`Port`；
- `IdentityFile`、`IdentityAgent`；
- `HostKeyAlias`；
- `StrictHostKeyChecking`；
- `UserKnownHostsFile`、`GlobalKnownHostsFile`。

首版检测到 `ProxyJump` 或 `ProxyCommand` 时返回 `SSH_UNSUPPORTED_CONFIG`，不得忽略后直连。

### 13.2 主机密钥

主机密钥验证先于用户认证：

- 已匹配：继续；
- 已撤销或不匹配：拒绝；
- 未知：仅在用户主动连接时展示指纹和 known_hosts 证据；
- 后台重连遇到未知或变化：拒绝，不弹窗；
- `accept-new`：只允许保存此前未知的主机密钥；
- `StrictHostKeyChecking=no/off`：首版返回不支持的配置，不静默降级。

known_hosts 写入使用用户的 OpenSSH 配置路径和 `0600` 权限。插件不建立第二套隐式信任库。

### 13.3 用户认证

首版支持 SSH agent 和无口令私钥。私钥路径只用于本次连接，日志中脱敏。

密码、私钥口令和 keyboard-interactive 在后续阶段加入。到时只允许用户主动操作触发安全输入，默认不持久化秘密。

默认关闭 agent forwarding。后续如增加开关，也只能按主机由用户显式开启。

## 14. 错误处理与日志

### 14.1 错误分类

| 错误码 | 含义 |
|---|---|
| `SSH_CONFIG_INVALID` | 配置缺失或字段非法 |
| `SSH_UNSUPPORTED_CONFIG` | 当前版本不支持的 SSH 配置 |
| `SSH_HOST_KEY_UNKNOWN` | 主机密钥尚未信任 |
| `SSH_HOST_KEY_CHANGED` | 主机密钥与信任记录冲突 |
| `SSH_AUTH_FAILED` | SSH 用户认证失败 |
| `REMOTE_PLATFORM_UNSUPPORTED` | OS、架构或 libc 不受支持 |
| `REMOTE_VERSION_MISMATCH` | 远端运行包与本插件选定的构建不一致 |
| `REMOTE_INSTALL_FAILED` | 下载、校验或自检失败 |
| `REMOTE_INSTANCE_UNAVAILABLE` | 原实例不存在或不健康 |
| `PLUGIN_TEMPLATE_PARTIAL` | 部分插件未安装或升级成功 |
| `CONFIG_SYNC_PARTIAL` | 部分配置或凭据未同步成功 |
| `TUNNEL_FAILED` | 本地网关或 SSH 数据通道失败 |
| `OPERATION_CANCELLED` | 用户取消 |
| `OPERATION_TIMEOUT` | 有界操作超时 |

UI 展示阶段、错误码和修复建议。命令非零退出与基础设施故障分开处理。

### 14.2 日志

日志包含连接 ID、实例 ID、阶段、耗时和结构化错误。默认过滤：

- SSH 密码、私钥口令和完整私钥路径；
- API Key、Token 和 OAuth 内容；
- DSH 访问令牌和完整认证 URL；
- HTTP Cookie 和认证头；
- 远程命令中的环境变量值。

下载、插件安装、配置同步和远程执行日志有大小上限。诊断导出默认使用脱敏副本。

## 15. 实施阶段

### 15.1 P0：技术验证

1. 自包含运行包能在没有 Node 和编译工具的 Linux x64 主机启动；
2. 本地版本变化能触发正确的远端安装或升级；
3. 静态资源、RPC、WebSocket、Cookie、Host 和 Origin 能通过 SSH 网关；
4. 同一标签页能完成本地到远端、远端到本地的整页切换；
5. 现有主题插件无需修改即可在远端工作；
6. 远端 Host 脱离启动 SSH 通道后仍存活，重连能恢复原 Session 与终端；
7. API Key 只写入远端 credentials，不出现在 patch、进程参数或日志中；
8. 远端插件安装不改变本地 profile。

任一验证失败都先调整部署或网关设计，不通过关闭认证或版本检查绕过。

### 15.2 P1：最小可用版本

- 本地 macOS/Linux，远端 Linux x64/arm64；
- SSH config 主机别名、agent 和无口令私钥；
- 严格主机密钥检查；
- 本机 DSH 版本与远端运行包版本解耦；
- 自动安装、升级、启动、接入和停止；
- 同标签页本地/远程整页切换；
- 文件、搜索、终端和 Agent；
- 本机插件快照、官方启停同步与远端插件页；
- 主题和模型提供商配置同步；
- 授权 API Key 写入远端 credentials；
- 基础断线重连；
- 主机管理页、同步差异和脱敏日志。

### 15.3 P2：体验补全

- 密码、私钥口令和 keyboard-interactive；
- ProxyCommand 和 ProxyJump；
- macOS 远端；
- 通用端口转发；
- 更完整的升级回滚与同步冲突界面；
- 高延迟、丢包和多窗口并发优化；
- 远程窗口连接诊断与断线详情。

### 15.4 P3：可选本地 Host 模式

只有在用户明确要求单窗口混合本地与远端工作区时，才评估核心 `executionTarget` 和插件双端模型。该阶段需要独立规格，不在本方案中预留隐式兼容承诺。

### 16.3 首版发布验收

1. 用户只准备可用的 SSH 主机别名，无需手动安装或升级远端 DSH。

7. 授权 API Key 只写入远端 credentials，秘密不出现在 patch、命令行或日志中。
8. SSH 断开不直接终止原 Host，恢复后能接入同一实例。
9. 重连不会重复执行结果不确定的工具、插件安装或配置同步操作。
10. 网关只监听回环地址，DSH 浏览器认证和插件安装批准保持开启。
11. 返回本地后，本地 profile、插件、配置和 Session 与切换前一致。

## 17. 工作包边界

后续实现拆成五个可独立评审的工作包：

1. **远端发行与 Remote Controller**：版本化运行包、安装升级、实例注册、Supervisor 和健康检查；
2. **SSH 控制面**：配置、认证、状态机、取消和重连；
3. **本地网关与切换导航**：HTTP/WebSocket 转发、可信来源、整页切换和返回本地；
4. **插件快照与配置同步**：快照脱敏、远程安装兼容检查、构建批准、配置白名单和 credentials 同步；
5. **DSH 插件 UI**：主机管理、进度、差异、日志和远程状态插件。

先做工作包 1、2、3 的 P0 验证。工作包 4 必须基于真实远端管理 API，工作包 5 使用真实连接状态，不用长期 mock 代替端到端验证。
