## 1. 目标与边界

SSH Remote 是按机器切换完整 DSH 工作环境的入口，不是管理页中的网页预览器。

- Desktop 在当前应用窗口内展示远端完整 DSH，覆盖本地应用内容，只保留简洁的环境切换栏。操作系统窗口按钮保留可用。
- 本地使用当前本地 profile；每个远端页面独立连接对应机器的 `web` profile。两端不共用 Client 运行时、插件图、配置或 Session。
- 本地、远端 A、远端 B 可以反复切换，普通切换不重建或重新加载远端页面。
- 返回本地恢复原本的本地 DSH，包括当前会话和导航状态，不渲染插件自制的“本地工作区”说明页。
- 主机管理、同步、端口与诊断是次级操作，不占用远端日常工作的内容区。
- 保留已经审核的 SSH、Controller、运行包、版本、实例和同步后端；重做 Client 展示与状态管理，修复必要的前后端衔接，不整体重写后端。

不增加 `executionTarget`，不恢复默认远端目录和插件模板，不实现持续双向配置同步。不新增独立 Web 服务、外部浏览器窗口或独立 Desktop 应用。

## 2. 用户操作

### 2.1 从本地进入

本地切换入口打开环境选择界面，列出本地、已打开远端和已保存主机。打开选择界面不先替换本地的会话或管理面板。

- 选择已打开的健康远端：显示原页面，不重新连接、同步或加载。
- 选择尚未打开的主机：执行连接流程；成功后进入远端整窗工作区。
- 没有主机：显示简洁的添加主机入口，不展示空的远端页面。
- 添加主机：从 OpenSSH 配置选择，保留手动输入已有别名的方式。
- 取消选择或选择本地：回到原本的本地界面。

Desktop 的切换入口直接控制插件自己的常驻工作区，不以切换中央 `main` 面板作为 Guest 存活的前提。普通浏览器继续保留主机管理页面入口。

### 2.2 远端整窗工作区

顶部仅保留本地与远端页签、关闭页签和管理入口。活动页签清楚标明主机；连接或失败状态可在该页签或工作区内显示。

切换栏以下全部交给远端 DSH：无本地侧栏、主机信息大标题、版本说明行、Guest 边框、圆角卡片和四周大留白。远端自己的侧栏、会话、文件、终端和插件页面属于远端内容。

布局随应用内容窗口变化，不使用固定最小高度强迫小窗口滚动，也不使用 `100vh` 减去猜测的宿主高度。窗口缩放后，Guest 填满切换栏下的剩余空间。

### 2.3 返回本地与管理设置

- 点击本地：共用页签栏保持不变，内容区显示原本的本地完整 DSH；远端页面在同级内容区中隐藏并保留。本地不是“退出远端模式”或返回管理页。
- 点击管理：进入次级管理视图，保留进入前的活动环境；Guest 隐藏但不卸载。
- 退出管理：回到进入前的环境；远端仍是同一个页面实例。
- 关闭活动远端页签：只关闭该 Guest，回到最近使用的其他已打开环境；没有其他远端时回到本地。
- 关闭非活动远端页签：不改变当前环境。

内嵌远端页面不再显示普通浏览器专用的“导航到本地地址”按钮。返回本地统一由外层切换栏负责。内嵌标识按页面设置，不能更改远端全局 profile，否则会影响同时连接的普通浏览器用户。

### 2.4 明确区分生命周期操作

| 操作 | Guest 页面 | 本地 SSH／网关 | 远端 Host 与任务 |
|---|---|---|---|
| 本地／远端／管理视图切换 | 保留，仅改变可见性 | 保持 | 保持 |
| 关闭远端页签 | 释放选中 Guest | 保持 | 保持 |
| 断开 SSH | 已开页签显示断开，不假装在线 | 关闭该连接 | 不停止 |
| 页面加载失败或渲染进程退出 | 显示对应失败页，可释放失效 Guest | 不误报为必然断开 | 不停止 |
| 停止远端 Host | 用户确认后显示已停止 | 按既有后端处理 | 显式停止 |
| 退出 Desktop／卸载插件 | 释放本地页面资源 | 释放本地连接与租约 | 不因此停止 |

页面关闭与 Host 停止不能共用一个“返回本地”操作。退出应用后不承诺恢复未持久化的网页草稿；远端任务、已保存 Session 和实例复用由远端 Host 与 Controller 负责。

## 3. Client 架构

### 3.1 常驻工作区与入口分离

目标结构是 DSH 外壳拥有一条持久环境页签栏和一个同级内容区域。内容区域内，本地原始界面与各远端 Guest 并列，切换只改变当前可见环境；会话和管理面板导航不决定这些页面的存活。

当前公开 `shell.overlay` 只能提供覆盖层，`main` 只分配中央面板；`shell.leading` 只在侧栏完全隐藏时提供左上窗口控制区域，不能充当持久全宽页签栏。当前 `layout` 服务没有为整个本地界面预留顶部区域的接口。不得通过替换 `root`、移动本地 DOM、猜测宿主类名改样式或另开本地 Guest 来伪造同级。

上述核对尚未得到满足全部约束的纯插件方案，不能据此转为修改 DSH 源码。下一步仅核对公开的插件组合与切换机制；若无法满足目标，应说明具体缺口，不新增宿主接口、不实施布局源码分支，也不交付仍然嵌套的版本。

入口只发出打开、选择或管理请求。Guest 与页签不归中央管理面板所有，因此中央面板或本地会话导航不销毁它们。

使用现有 Desktop browser `acquire`、`release`、`onOpenRequested` 与沙箱 `webview`。不依赖可选的 `views` API，不扩展 Guest 对本机文件、Node 或 Desktop bridge 的访问权限。

### 3.2 职责拆分

| 单元 | 职责 | 不负责 |
|---|---|---|
| 环境导航状态 | 当前环境、管理返回目标、最近使用顺序 | 连接、配置写入 |
| 远端页面控制器 | 每台主机的 Guest、加载代次、显示状态、释放 | 远端进程生命周期 |
| 主机管理视图 | 使用现有 API 添加主机、连接、同步、诊断 | 持有或销毁 Guest |
| 连接结果适配 | 接收实例／地址变化，决定复用、重试或重建 | 在普通切页签时重放副作用 |
| 同步结果展示 | 备份元数据、部分失败和复制处理提示 | 读取或显示秘密值 |

组件回调和状态更新不得引起 Guest 重建。异步完成结果必须核对主机与加载代次；旧页面迟到的 ready/error 不能覆盖新页面状态。

### 3.3 状态与秘密边界

环境状态与连接状态分开：页面可见不代表 SSH 在线，SSH 在线也不代表 Guest 加载成功。

每个远端页签至少记录主机 ID、显示名称、当前实例身份、加载代次和页面状态。页面状态包括未加载、加载中、可用、断开、失败、已停止。

认证 URL 仅在当前连接的内存中使用，不写入页签标签、诊断、普通日志或持久化 UI 状态。正常切换复用同一个 Guest；关闭、显式重试或必要的端点变更才改变其生命周期。

插件真正卸载或整个文档重载仍会结束 Guest 生命周期。不能把常驻层设计当作“自动跳回”已经修复的证据：必须记录并复验实际面板、卸载、导航和 Guest 事件。

## 4. 连接、错误与重连

1. 连接流程保留 SSH 验证、运行包校验、实例接入、网关和首次同步顺序。失败时保留当前操作上下文与具体阶段。
2. 同一健康页签的普通切换不调用 acquire 或 loadURL。
3. 对失效 Guest 的显式重试，或实例／有效连接地址变化，采用新的加载代次，更新地址并恢复或重建一次页面。
4. 已关闭页签的迟到 acquire 必须释放，不能重新出现。重复关闭保持幂等。
5. 同一代的重复连接或 ready 通知不能产生多个 Guest。
6. 自动重连沿用后端限制，不请求新秘密或信任批准，不重放工具、配置同步、插件安装等副作用。
7. 错误留在对应主机页签，显示原因与重试入口，不自动选择本地。外部链接失败不应伪装成整个远端已经断开。
8. 返回本地不会加载本地 URL 到远端 Guest；普通浏览器的整页返回保持可用。

增加有界、脱敏的 UI 生命周期诊断：主机、加载代次、创建／释放／显示／隐藏、失败类型和事件码。不得记录认证 URL、Cookie、密钥或令牌。诊断用于确认实际跳回原因，不先假定是加载失败或插件重载。

## 5. 首次同步与备份结果

保留现有后端策略：首次连接默认同步所有支持的用户配置和已配置 API Key，后续连接不自动重放；覆盖远端已有配置前先创建远端私有备份。

修复展示链路：

- 成功与部分失败都接收完整同步结果。成功不能丢弃备份元数据和人工处理提示。
- 提示按主机保留，在切换远端、本地或管理视图后仍可在主机详情找到，不依赖一次性弹窗。
- 远端工作区可用不代表人工合并已经完成，二者独立展示。
- 复制内容包含远端备份路径、profile 和逐项保留／恢复／合并约束，不包含配置值或秘密。
- 用户在当前远端新会话处理备份；本插件不自动发起合并、恢复或再次覆盖。
- 本轮不改变 API Key 的 credentials 写入方式，不以修复提示为由重新执行首次同步。

远端插件页继续区分本机快照与远端实时状态；安装、启停和卸载只作用于当前远端，构建批准和版本限制保持不变。

## 6. 验收条件

### 6.1 真实 Desktop 验收

| 场景 | 通过条件 |
|---|---|
| 远端连接成功 | 当前窗口显示远端完整 DSH；切换栏外无本地管理外框；未打开外部浏览器 |
| 窗口缩放 | 大、小、窄、矮窗口中 Guest 都填满可用内容区，无固定空白区；窗口按钮可用 |
| 远端 A → 本地 → A | 返回原本本地 DSH，再回到 A 时仍为原页面、原会话、原滚动位置 |
| A → B → A | 两端页面彼此独立，普通切换不重新加载 |
| A → 管理 → A | 保留同一 Guest，不重新 acquire／load，不释放 |
| 关闭 B | 只释放 B，不停止 A 或远端 Host |
| 加载失败／渲染退出 | 留在该主机的失败页；重试可创建一个新 Guest，不卡在已失败页签 |
| 网关／实例地址变化 | 使用新连接结果恢复页面，不能丢弃新地址或继续使用旧认证 URL |
| 返回本地 | 统一切回外层本地环境，Guest 内不出现嵌套的本地 DSH |
| 首次同步成功且有备份 | 能找到并复制处理提示；随后普通重连不重复备份或写入 |
| 退出 Desktop 后重连 | 原远端健康实例与任务继续存在；运行包身份匹配后复用，不因退出而重启 Host |
| 插件卸载／重载 | 资源无泄漏；行为与普通切换区分，记录实际是否发生界面回退 |

先用不涉及真实 SSH 的本地测试页面验证 Electron 的尺寸和 Guest 生命周期，再用已授权的专用测试主机验证完整流程。不访问任意用户主机或读取私钥来取得验收证据。

### 6.2 自动回归

- 使用真正执行 React effect 与状态更新的生命周期测试，而非只测试辅助函数。
- 覆盖普通切换不重建、管理／本地面板导航不卸载、双主机独立、显式关闭、迟到 acquire 和旧代回调。
- 失败自动清理必须在测试主动 close 之前断言，避免测试替实现执行清理。
- 覆盖新地址、失败页签重试、成功同步备份提示保留、普通浏览器兼容。
- 原有 SSH、运行包、同步、插件管理与实例生命周期回归不减少。

代码完成、模拟测试通过、插件激活和真实 Desktop 验收分别记录。没有真实截图与操作结果时，不标记整窗与状态保留验收通过。

## 7. 实现顺序与变更控制

1. 用户确认本规格。
2. 拆分常驻工作区、环境导航和 Guest 控制器，补生命周期回归。
3. 实现全窗口布局、真实本地切换和次级管理视图。
4. 修复失败重试、新连接地址、内嵌返回和备份结果展示。
5. 审查差异，运行原有回归，再通过正式插件安装入口更新当前 profile。
6. 验证真实 Desktop；根据实际证据修复问题，再更新验收记录。

本规格批准前不改业务代码、不重新安装插件、不发起远端连接。实现期间不顺带重构不相关后端，不用模拟页面截图替代已安装插件的验收。
