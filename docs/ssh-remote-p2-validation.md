### 普通浏览器跳转前的备份检查

[浏览器连接回归](<../test/p2/ui/browser-connect-review.test.mjs>)先复现了跳转早于备份检查、部分同步对话框缺少复制入口、页面卸载后的迟到跳转。初始 9 项有 7 项失败；修复并补充请求顺序与地址校验后，12 项全部通过。

- 普通浏览器收到待检查备份时，先显示复制、取消和继续入口。取消不跳转；复制失败保留提示，不显示底层错误中的地址。
- Desktop 正常成功连接仍直接打开 Guest；部分同步仍需确认，对话框内可复制备份处理指令。

- 继续操作检查主机与请求编号；旧回调不能消费新连接的地址，重复点击不会重复跳转。
- 较早的连接结果或错误不能覆盖当前请求的提示、忙状态和跳转目标；已经完成的合法备份元数据仍可保留。

## 默认全量同步与远端备份

根据后续反馈，配置同步最终采用以下规则：

- 只有首次添加并连接时默认同步所有支持的用户配置和已配置 API Key；后续连接不重放。
- 自动发现支持的 settings 和 schema 声明的凭据，不要求用户逐项选择命名空间或填写 credential refs。
- 剔除秘密配置路径、本机路径、本地基础设施、当前 cwd、存储和运行时配置。
- 凭据通过远端 `credentials.set()` 写入 DSH 管理的 `<DSH_HOME>/.credentials.yaml`，不手写 `.env`。
- 首次覆盖远端已有用户配置或插件状态前，先调用远端备份 API。
- 备份保存在远端 `web` profile 的 `.ssh-remote-backups/`，目录权限 `0700`、文件权限 `0600`，本地只获得元数据。
- 需要人工合并时，管理页提供可复制的提示词，供用户在当前远端开新会话逐项保留、恢复或合并；提示词不包含配置值或秘密。

真实 VM 已验证：首次备份、备份文件 mode 0600、配置与凭据同步、后续连接不重复备份或写入、手动预览与冲突确认。相关真实测试 `2/2` 通过，实例均已停止。
